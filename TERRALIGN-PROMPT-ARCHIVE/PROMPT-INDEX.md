## 3. Operational Integrity & Security Rules
1. **Verbatim Preservation**: No prompt may be paraphrased, compressed, or summarized. Original raw markdown must be retained.
2. **Immutability**: Once executed, prompt files are immutable. Revisions must be archived as distinct versions (`v1.1`, `v2.0`) with corresponding entries in `PROMPT-CHANGELOG.md`.
3. **No Secret Leakage**: Environment variables, authentication tokens (e.g. Supabase, Stitch), or personal credentials must never be included in prompt files or index tables.
4. **Distinction of States**:
   - `Draft`: Formulated but not yet approved for agent dispatch.
   - `Approved`: Signed off by product lead, ready for execution.
   - `In Execution`: Active in the current context.
   - `Executed`: Completed and empirically validated.
   - `Superseded`: Replaced by a newer version (referenced by ID).
